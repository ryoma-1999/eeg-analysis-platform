## 1. 本文書の目的

本文書では、EEG Analysis PlatformのFrontend、Backend APIおよび信号処理が仕様どおり動作することを確認するためのテスト項目、入力、操作、期待結果および合格基準を定義する。

現時点ではテストFrameworkによる自動テストを実装していないため、本書の中心は手動結合試験である。信号処理については、周波数が既知の人工信号を使用し、結果を目視および数値で確認する。

## 2. テスト方針

本Prototypeでは以下の層を対象とする。

| 層 | 主な確認内容 | 現在の方法 |
|---|---|---|
| 静的検査 | TypeScript、Lint、Build | Command実行 |
| Backend API | Status、Request、Response、Error | Swagger UI／Frontend |
| 信号処理 | Filter、PSD、Band Power | 人工信号による結合試験 |
| Frontend | State、Button、Chart、切替 | Browser手動操作 |
| System | Frontend–Backend接続、CORS | Docker Composeで結合試験 |

### 2.1 合格の基本条件

- 期待するHTTP StatusとResponse形式になる。
- 画面に未処理例外や不正な値が表示されない。
- Browser ConsoleとBackend Logに想定外のErrorがない。
- 既知周波数の人工信号について、期待する周波数成分を検出できる。
- OriginalとFiltered、異なるCSVの結果が混在しない。

### 2.2 信号処理試験の考え方

信号処理の厳密な自動判定Toleranceは未実装である。現在の手動試験では以下を最低基準とする。

- 10 Hz正弦波のPSD Peakが10.0 Hzになる。
- 10 Hz＋60 Hz信号へ40 Hz Low-passを適用すると、60 Hz成分が明確に減衰し10 Hz成分が残る。
- 10 Hz正弦波のDominant BandがAlphaになる。

将来の自動テストでは、通過帯域の振幅誤差と阻止帯域の減衰量をdBで定量化する。

## 4. テストデータ

Repositoryの`sample-data/eeg`に以下を配置している。

| ファイル | Channel | Sample | fs | Duration表示値 | 用途 |
|---|---:|---:|---:|---:|---|
| `eeg_test.csv` | 4 | 10 | 250 Hz | 0.036秒 | 最小Upload確認 |
| `eeg_filter_test_10hz_60hz_250hz.csv` | 1 | 2000 | 250 Hz | 7.996秒 | Filter検証 |
| `eeg_psd_test_10hz_250hz.csv` | 1 | 1000 | 250 Hz | 3.996秒 | PSD・Band Power検証 |
| `eeg_realistic_30s_250hz_8ch.csv` | 8 | 7500 | 250 Hz | 29.996秒 | 複数Channel・Slider・負荷確認 |

`duration`は`sampleCount / fs`ではなく、末尾時刻と先頭時刻の差である。このため1000 samples・250 HzのCSVは4.000秒分のSampleを持つが、APIの`duration`は3.996秒となる。

### 4.1 Filter試験信号

`eeg_filter_test_10hz_60hz_250hz.csv`のC3は、振幅1の10 Hz正弦波と振幅1の60 Hz正弦波を加算した人工信号である。

```math
x(t) = \sin(2\pi \cdot 10t) + \sin(2\pi \cdot 60t)
```

### 4.2 PSD試験信号

`eeg_psd_test_10hz_250hz.csv`のC3は、振幅1の10 Hz正弦波である。

```math
x(t) = \sin(2\pi \cdot 10t)
```

10 Hzは現在の帯域定義ではAlpha（8 Hz以上13 Hz未満）に含まれる。

## 8. Filter試験

### FLT-001 Filter未選択

1. `eeg_filter_test_10hz_60hz_250hz.csv`をUploadする。
2. 全FilterをOFFのまま`Apply Filter`を押す。

期待結果：

- APIが成功する。
- `highpassHz`、`lowpassHz`、`notchHz`はすべて`null`になる。
- Originalとほぼ同じ値のFiltered EEGが返る。
- 表示がFilteredへ切り替わる。

### FLT-002 40 Hz Low-pass

1. Filter試験信号をUploadする。
2. Low-passだけをON、`40 Hz`へ設定する。
3. Filterを実行する。
4. FilteredのPSDを計算する。

期待結果：

- Original PSDでは10 Hzと60 Hz付近にPeakが見える。
- Filtered PSDでは60 Hzが明確に減衰する。
- 10 Hz成分は60 Hz成分より強く残る。
- Filter設定表示値は`lowpassHz=40`である。

### FLT-003 60 Hz Notch

1. Filter試験信号をUploadする。
2. NotchだけをON、`60 Hz`へ設定する。
3. Filterを実行してPSDを計算する。

期待結果：60 Hz付近が選択的に減衰し、10 Hz成分が残る。

### FLT-004 Band-pass

1. High-passを`8 Hz`、Low-passを`13 Hz`に設定する。
2. Filter試験信号へ適用する。

期待結果：10 Hz成分が残り、60 Hz成分が減衰する。

### FLT-005 周波数大小関係エラー

High-passを`40 Hz`、Low-passを`10 Hz`にして実行する。

期待Status：`400 Bad Request`

期待Detail：`High-pass frequency must be lower than low-pass frequency.`

Frontend期待結果：Panel内に同Messageが表示され、Buttonが`Apply Filter`へ戻る。

### FLT-006 Nyquist以上

250 Hzデータに対してLow-passを`125 Hz`以上に設定する。

期待Status：`400 Bad Request`

期待Detail：`Low-pass frequency must be below the Nyquist frequency.`

### FLT-007 0以下

APIからHigh-pass、Low-passまたはNotchへ`0`以下を送る。

期待Status：`400 Bad Request`

期待結果：対象Filterについて`must be greater than 0 Hz.`が返る。

### FLT-008 Originalからの再計算

1. OriginalへFilter Aを適用する。
2. Filtered表示のまま設定を変更してFilter Bを実行する。
3. Filter Bの結果を確認する。

期待結果：Filter BはFilter Aの結果へ重ねず、Original EEGへ直接適用される。

### FLT-009 Original／Filtered切替

Filter成功後にOriginalとFiltered Buttonを交互に押す。

期待結果：

- 波形が選択信号へ切り替わる。
- Original EEGはFilter前のまま保持される。
- ButtonのActive表示が正しく変わる。

## 15. 今後追加する自動テスト

優先度順に以下を追加する。

### 15.1 Backend Unit Test

`pytest`を導入し、Service関数を直接検証する。

- 10 Hz＋60 Hz信号へ40 Hz Low-passを適用する。
- FFTまたはPSDから10 Hzと60 Hzの振幅を求める。
- 10 Hzの保存率と60 Hzの減衰率をToleranceで判定する。
- 10 Hz正弦波のPSD Peakを`10.0 ± 0.5 Hz`で判定する。
- 10 Hz正弦波のAlpha Powerが最大になることを判定する。
- NaN、空配列、Nyquist条件等の`ValueError`を判定する。

### 15.2 API Test

FastAPIの`TestClient`または`httpx`を使用する。

- 各EndpointのStatus CodeとResponse Schema
- Upload異常系の`detail`
- Pydanticによる`422` Response
- Serviceの`ValueError`から`400`への変換

### 15.3 Frontend Test

VitestとReact Testing Libraryの導入候補：

- EEG未読込時のButton無効化
- Upload成功Callback
- Filter OFF時に`null`を送ること
- Props変更時のPSD／Band Power結果Reset
- Channel選択によるGraph Data切替

### 15.4 End-to-End Test

Playwright等で以下を自動化する。

- CSV Uploadから波形表示まで
- Filter実行とOriginal／Filtered切替
- PSD・Band Power計算
- Error Message表示

### 15.5 CI

GitHub Actions等でPull Request／Push時に以下を実行する。

```text
Frontend Build
→ Frontend Lint
→ Backend Unit Test
→ API Test
→ 必要に応じてE2E Test
```

テストデータとToleranceを固定し、ライブラリ更新や信号処理変更による数値結果の変化を検出できる状態を目標とする。
