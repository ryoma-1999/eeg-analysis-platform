# システム概要

## 1. システム名

EEG Analysis Platform

## 2. 目的

本システムは、CSV形式で保存されたEEG（Electroencephalogram：脳波）データをWebブラウザから読み込み、前処理、周波数解析および可視化を行うためのプロトタイプである。

EEG解析では、記録された時系列データをそのまま確認するだけでなく、不要な周波数成分の除去や、信号に含まれる周波数特性の把握が必要になる。本システムでは、以下の処理を一つの画面から実行できるようにする。

- EEG波形の確認
- High-pass、Low-pass、Notchフィルタによる前処理
- PSD（Power Spectral Density：パワースペクトル密度）の計算
- Delta、Theta、Alpha、Beta、Gamma帯域のBand Power計算
- Original信号とFiltered信号の比較

また、将来的な欠損データ補完、リアルタイム解析、AIによるEEG分類機能を追加できる構成を目指す。

## 3. システムの特徴

### 4.1 Webブラウザから操作可能

利用者は専用の解析ソフトウェアを直接操作するのではなく、WebブラウザからCSVファイルをアップロードし、解析条件の設定と結果の確認を行う。

### 4.2 FrontendとBackendの責務を分離

Frontendは画面表示、ユーザー操作およびグラフ描画を担当する。BackendはCSVの検証、フィルタ処理、PSD計算およびBand Power計算を担当する。

この分離により、画面と信号処理を独立して変更しやすくする。

### 4.3 Originalデータを保持

フィルタ処理を実行しても、アップロード時のOriginal EEGデータは上書きしない。フィルタ後のデータを別に保持し、画面上でOriginalとFilteredを切り替えられる。

### 4.4 複数チャンネルへ対応

CSVの `time` 列以外をEEGチャンネルとして読み込み、複数チャンネルの波形、PSDおよびBand Powerを扱う。

### 4.5 Dockerによる実行環境の統一

FrontendとBackendをそれぞれDockerコンテナとして起動し、Docker Composeでまとめて管理する。開発環境による依存関係の違いを小さくし、同じ手順で実行できるようにする。

## 4. 入力データ(変更の可能性あり)

入力はCSV形式とし、次の構造を前提とする。

※今後、EDFやBDFを読めるようになる必要あり

| 列 | 内容 |
|---|---|
| `time` | 各サンプルの計測時刻（秒） |
| その他の列 | EEGチャンネルごとの信号値 |

例：

```csv
time,Fp1,Fp2,C3,C4
0.000,1.2,0.8,-0.4,0.1
0.004,1.1,0.7,-0.3,0.2
0.008,1.3,0.9,-0.5,0.0
```

Backendは `time` 列の差分中央値からサンプリング周波数を推定する。

```text
sampling rate = 1 / median(time difference)
```

また、先頭時刻と末尾時刻の差から記録時間を計算する。

```text
duration = last time - first time
```

現在のCSV読込では、以下を検証する。

- 拡張子がCSVであること
- CSVが空でないこと
- `time` 列が存在すること
- EEGチャンネルが1つ以上存在すること
- 時刻とEEGデータが数値であること
- EEGデータに欠損値がないこと
- 2サンプル以上存在すること
- 時刻が単調増加していること

## 5. 主要機能

| 機能 | 概要 | 状態 |
|---|---|---|
| CSVアップロード | EEGデータをCSVから読み込む | 実装済み |
| CSV検証 | 列、数値、欠損値、時刻順序などを検証する | 実装済み |
| データ情報表示 | ファイル名、チャンネル数、サンプリング周波数、記録時間を表示する | 実装済み |
| EEG波形表示 | 複数チャンネルの時系列波形を表示する | 実装済み |
| 時間範囲移動 | 10秒分の波形を表示し、時間スライダーで表示範囲を移動する | 実装済み |
| 信号切替 | OriginalとFilteredを切り替える | 実装済み |
| High-pass Filter | 指定周波数未満の低周波成分を減衰させる | 実装済み |
| Low-pass Filter | 指定周波数を超える高周波成分を減衰させる | 実装済み |
| Notch Filter | 指定周波数付近の成分を減衰させる | 実装済み |
| PSD | Welch法により周波数ごとのパワーを計算する | 実装済み |
| Band Power | 各EEG周波数帯域のパワーを計算する | 実装済み |
| APIヘルスチェック | Backendの稼働状態を画面に表示する | 実装済み |
| 欠損データ補完 | 欠損区間を検出・再構成する | 未実装 |
| リアルタイム解析 | EEGをリアルタイムに受信・解析する | 未実装 |
| AI解析 | 登録したAIモデルでEEGを分類する | 未実装 |
| Azure公開 | クラウド環境へデプロイする | 未実装 |

## 7. システム構成の概要

本システムは、FrontendとBackendから構成される。

1. 利用者がFrontendへCSVファイルを指定する。
2. FrontendがFastAPIのEEG Upload APIへファイルを送信する。
3. BackendがCSVを検証し、EEGデータ、サンプリング周波数、記録時間などを返す。
4. FrontendがEEG波形とデータ情報を表示する。
5. 利用者の操作に応じて、FrontendがFilter、PSDまたはBand Power APIを呼び出す。
6. Backendが信号処理を実行し、解析結果をFrontendへ返す。
7. Frontendが返却された結果をグラフとして描画する。

詳細な構成は [02_システム構成.md](./02_システム構成.md)、処理ごとのデータの流れは [03_データフロー.md](./03_データフロー.md) に記載する。

## 8. 現在の制約

現在のプロトタイプには、以下の制約がある。

- CSV入力のみ対応している。
- `time` 列の存在を必須とする。
- 欠損したEEG値を含むCSVは受け付けない。
- サンプリング周波数はCSVの時刻差分から推定する。
- データは永続化せず、Frontendの状態として保持する。
- ユーザー認証および権限管理は実装していない。
- リアルタイム入力には対応していない。
- AIモデルによる分類は実装していない。
- APIの接続先は現在 `http://localhost:8000` に固定されている。
